# Repository guidance for coding agents

## Project overview

This repository is a Terraform provider for the current Microsoft Foundry Agent Service. It uses Go, Terraform Plugin Framework, Plugin Protocol 6, and Azure Identity.

The initial scope is provider wiring only. Do not add resources, data sources, deprecated Assistants API support, classic agent support, or API-version-suffixed Terraform names unless a task explicitly requests them.

## Layout

- `main.go` starts the protocol 6 provider server.
- `internal/provider` owns provider schema, environment fallback, validation, and client configuration.
- `internal/clients` contains the concrete Foundry HTTP client.
- `examples/provider` contains the executable provider example.
- `templates` contains terraform-plugin-docs templates.
- `docs` is generated by terraform-plugin-docs.

Keep the client concrete. Add narrow interfaces beside a consuming resource only when that resource needs a test fake.

## Commands

Use Go 1.25 or later.

```shell
go mod download
make test
make lint
make docs
make check
```

`make check` is the full offline validation path. It formats code, runs vet and lint, executes tests, builds the provider, regenerates docs, and validates examples with installed Terraform and OpenTofu CLIs.

Run a focused Go test with:

```shell
go test ./internal/provider -run TestResolveConfig
go test ./internal/clients -run TestClientRequestAndRetry
```

## Implementation rules

- Support Go 1.25, Terraform 1.11, and OpenTofu 1.11 as the minimum versions.
- Keep `providerserver.Serve` on protocol 6.
- Provider arguments override environment variables, including explicit false and empty values.
- Reject unknown configuration values, incomplete credentials, and multiple authentication modes with clear diagnostics.
- Keep API key authentication mutually exclusive with Microsoft Entra ID authentication.
- Default to Azure CLI when no authentication mode is configured. Require explicit `use_msi` or `use_oidc` selection and do not add a `DefaultAzureCredential` fallback.
- Prefer OIDC in automation docs, then managed identity, certificate, client secret, and Azure CLI for local work.
- Use `http.RoundTripper` as the transport seam.
- Keep retries bounded and context aware. Preserve `x-ms-client-request-id` across retries and include service request IDs in errors.
- Keep environment endpoint suffixes, token scopes, and API versions inside the client. The current API default is `v1`.
- Use write-only schema attributes for future resource secrets so Terraform does not store them in plans or state.
- Add import support for durable resources when resources are introduced.
- Do not add an abstraction, dependency, feature flag, or compatibility layer without a current caller.

## Tests

Unit tests must stay offline and deterministic. Provider configuration tests cover environment fallback, provider precedence, authentication conflicts, incomplete credentials, and unknown values.

Use injected transports for HTTP tests. Do not commit recorded credentials, tenant endpoints, state files, generated binaries, or acceptance-test artifacts.

Credentialed acceptance tests belong in protected workflows and must use `TF_ACC=1`. Do not run them in pull requests from untrusted forks.

## Documentation

`docs/index.md` is generated. Edit `templates/index.md.tmpl`, provider schema descriptions, or examples, then run `make docs`.

Keep `README.md`, examples, and CI commands consistent. Update `CHANGELOG.md` for user-visible behavior.

## Pull requests

Keep changes focused. Run `make check` before submitting. Include tests for behavior changes and documentation when configuration or user-facing behavior changes.

Contributors sign commits with the Developer Certificate of Origin:

```text
Signed-off-by: Name <email@example.com>
```

Do not create or publish releases during ordinary development.
